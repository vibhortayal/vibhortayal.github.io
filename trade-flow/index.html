Privacy by design

Your server. Your schedule. Your keys.

Raw chat and WhatsApp identities never reach the dashboard. The pipeline sends each message to the language model you configure for extraction, then stores only structured, pseudonymized trade records.

  • Stable pseudonyms replace names and phone numbers
  • Secrets and the WhatsApp session stay on your machine
  • Hourly pull-and-disconnect — no permanent session
  • Open-source code makes every data boundary inspectable
How it works

The complete pipeline, yours to inspect.

The MIT-licensed repository includes the reader, parser, outcome scorer, setup UI, database schema, and dashboard. Run it on your own hardware — a free Oracle Cloud VM is enough — and keep control of every connection.

01

Pull

Connect as a linked device, fetch messages since the last checkpoint, disconnect. Hourly, 06:00–18:00.

02

Parse

Split buys, sells, plans, options, and quoted context into structured trade actions.

03

Score

Check five-trading-day direction and closed round trips against market data.

04

Explore

Review flow, outcomes, clusters, and trader activity on the dashboard.

The stack

Boring tools, composed well.

Chat reader

whatsapp-web.js

Connects as a linked device, pulls messages since the last checkpoint, and disconnects. No permanent session, no spare phone.

Language model

Gemini API · free tier

Turns messy chat messages into structured trade records — symbol, action, instrument, strike, expiry, quoted context included. Any OpenAI-compatible LLM works instead.

Market data

TradingView

Daily bars power the five-trading-day outcome scoring, round-trip detection, and target-hit checks. Yahoo Finance (free, no key) works as a drop-in alternative.

Database

Supabase · free tier

Postgres stores the pseudonymized trade records and sync metadata. The dashboard reads it live; row-level security keeps writes server-side. Any PostgREST-compatible database works.

Runtime

Node.js + Python

Node drives the WhatsApp reader and setup UI; Python handles extraction, scoring, and the database push. One shell script runs the whole cycle.

Hosting

Vercel + Oracle Cloud · free

The dashboard is a dependency-free static site on Vercel; the pipeline runs on an Oracle Cloud Always Free VM. Any Ubuntu VM works as the host.

Each layer is swappable — the stack above is the free-tier default, not a requirement. Any Ubuntu VM, any OpenAI-compatible LLM, any PostgREST database works.

The setup prompt

Set up Trade Flow end to end: https://github.com/vibhortayal/wa-trade-bot WHAT IT IS: an hourly pipeline on a VM. A WhatsApp linked-device reader pulls new messages from one trading group, an LLM (Gemini by default, any OpenAI-compatible API works) extracts structured trade actions, market data (TradingView by default, Yahoo Finance works too) scores each outcome over five trading days, and pseudonymized records land in Postgres (Supabase by default, any PostgREST endpoint works) for a static dashboard. PREREQUISITES — I have all of these ready: - Oracle Cloud Always Free account (any Ubuntu VM works; Oracle is the free suggestion) - Ubuntu 24.04 ARM VM (Ampere A1: 4 OCPUs / 24 GB RAM) with a public IP; subnet security list allows TCP ingress on port 3001 from 0.0.0.0/0 - My WhatsApp account on my phone (I can type in a pairing code) - Gemini API key (free tier; or any OpenAI-compatible LLM base URL + key + model) - Supabase project URL + service_role key (or any PostgREST endpoint) - TradingView account (for outcome scoring; or use free Yahoo Finance instead) DO THIS IN ORDER. Verify each step before moving on. 1. DEPLOY THE CODE Copy the repo to the VM. The VM directory is NOT a git repo — always deploy with scp, never git pull there: scp -r . ubuntu@<VM-IP>:~/wa-trade-bot SSH in and install (Node 20, Python 3, Chromium, systemd units). It asks for a setup-UI admin password — have me choose one: ssh ubuntu@<VM-IP> bash ~/wa-trade-bot/deploy/install.sh 2. OPEN THE SETUP UI http://<VM-IP>:3001/setup.html — HTTP Basic Auth, any username + the admin password from step 1. (Plain HTTP: fine for setup over a trusted network; don't expose it more broadly than needed.) 3. LINK WHATSAPP In the UI, enter my phone number in international format (e.g. 15551234567) and get the pairing code — hand it to me immediately, codes expire. I type it into WhatsApp → Settings → Linked devices → "Link with phone number instead". Confirm the UI reports wa_paired: true before continuing. 4. SAVE THE KEYS In the UI, paste the Gemini API key, the Supabase URL, and the Supabase service_role key. Then run the SQL shown in the UI's schema box once in the Supabase SQL editor — it creates the wa_trades and wa_meta tables with anon read-only access. Leave GEMINI_MODEL unset; the default model is used. 5. SET THE GROUP In the setup UI, enter the trading group's name in the "WhatsApp group to watch" field and save (it also shows the current value, and you can change or reset it any time). Alternatively, set WA_GROUP_QUERY in ~/wa-trade-bot/.env over SSH. (Substring match on the WhatsApp group name; the reader only touches group chats and stays within this one group.) 6. CONNECT TRADINGVIEW (outcome scoring) In the UI: pick the market-data source first. For TradingView, start the auth, open the authorize URL, approve it, then paste the full callback URL (the one containing ?code=...) back into the UI -- tokens stay on the VM. For Yahoo Finance there is nothing to connect. Skip this if I don't need outcome scoring. 7. RUN THE FIRST CYCLE In the UI press "Run a cycle now" — or over SSH: MANUAL_RUN=1 bash ~/wa-trade-bot/run-cycle.sh It pulls recent messages, parses trades, scores outcomes, and pushes to Supabase. Verify the cycle exits 0 and new rows appear in the wa_trades table. 8. CONFIRM THE SCHEDULE sudo systemctl status wa-trade-bot-cycle.timer — the hourly pipeline runs 06:00–18:00 America/Los_Angeles only. Never schedule it overnight. 9. OPEN THE DASHBOARD http://<VM-IP>:3001/ — it reads live from Supabase. HARD RULES - Never print, log, or commit: .env contents, data/messages.jsonl (raw chat), data/pseudonyms.json, phone numbers, sender names, group IDs, API keys, the admin password, or pairing codes. They are gitignored — keep them that way. - No git pull on the VM. Ever. Deploy with scp. - PUPPETEER_EXECUTABLE_PATH must be /snap/chromium/current/usr/lib/chromium-browser/chrome (the real binary). /snap/bin/chromium does NOT work inside systemd services. - Keep whatsapp-web.js's default Chrome/101 user agent; newer user agents land on WhatsApp's unsupported-browser page. - If anything fails, show me the exact error plus the log tail (the UI "Logs" section, or logs/cycle.log on the VM) before retrying.
